# Title: Reading a Network's Activations from Its Weights Alone: the ARC White-Box Estimation Challenge

## Keywords
white-box estimation, ReLU MLP, weight statistics, activation prediction, compute-limited inference

## TL;DR
Given only the weight matrices of a randomly initialized deep ReLU MLP, how well can the mean activation of every hidden neuron under Gaussian input be predicted, and how cheaply? Investigate this on the ARC White-Box Estimation suite.

## Abstract
A deep ReLU network is a fixed mathematical object once its weights are known, yet most of what we know about its behaviour is obtained by running inputs through it. The ARC White-Box Estimation Challenge asks how much of that behaviour can be read off the weights directly. Each instance is a square MLP of depth 32 and width 256: 32 weight matrices of shape (256, 256), with no biases, applied as x_{l+1} = max(x_l @ W_l, 0) to an input x_0 drawn from a standard normal distribution N(0, I). The target for an instance is the matrix of shape (32, 256) whose entry (l, j) is the expected activation of neuron j after layer l, the mean of the post-ReLU value over the input distribution. The public suite provides about one hundred such MLPs together with their target matrices (computed by large Monte-Carlo forward simulation), so that estimators can be developed and validated locally. Scoring on hidden MLPs uses the mean squared error between the predicted and true final-layer means, multiplied by max(0.1, C/B), where C is the number of floating-point operations the estimator spends on that MLP and B = 2.72e11 is the per-instance compute budget; lower is better. Spending the full budget on forward simulation is therefore the trivially expensive extreme, and the scientific question is what structure of the weights (norms, spectra, correlations between layers, the geometry of ReLU gating, or anything else) lets one predict the activation profile far more cheaply, and how the error grows with depth. An estimator is a self-contained Python class with a predict(mlp) method that returns the (32, 256) matrix from mlp.weights (a list of 32 arrays), mlp.depth and mlp.width, using only numpy and the standard library at prediction time, with any learned parameters embedded in the file. Contributions typically compare two to four materially different estimation approaches under identical conditions and report accuracy against the local ground truth alongside the compute they spend. The computational setting is self-contained: work runs offline with the provided records, numpy, scipy, scikit-learn and PyTorch on one GPU, without downloads.
