# 01/02 框架"跑不出分数"系统性根因报告

作者: Dawei Wang（执行: Claude Code）· 2026-08-29
状态: 战役因 API 额度耗尽暂停;本报告为截至暂停时的完整结论,全部论断附留存 run 证据。

## 一、结论

**分数出不来,不是研究做不出来,而是做出来的研究送不到打分链路手里。**
交付契约(写哪些文件/放哪/什么 schema/什么接口/多少时间)在"评测系统 → agent"的传递路上
层层丢失,而校验链路 fail-closed:差一列、差一个键名、差一个目录,99% 完成的研究判 0 分。

已验证:修复交付链后,01 在 ARC 得 **0.0909 / 0.0875**(含全新克隆复现)、PsyDefDetect
得 **0.1070**,validator finished 零警告——证明框架与模型的研究能力从来不是瓶颈。

## 二、三个断层(两框架共有)

### ① 空间断层——产物写在打分员看不见的地方
- 01 两容器拓扑:agent 可写世界映射到 `workplace_paper/task_*/workplace/workplace/`,
  校验器只看 `/workspace` 根。(01×ARC 42 门,前 5 次全灭;搬运桥后通过)
- 02 BFTS 树:成果在 `experiments/*/logs/best_solution_*.py`,不在根。
- 01×mcar local-exec:`/project` 无嵌套容器时是普通目录,随容器退出蒸发
  (fullrun_mcar_01_20260828_142606:完整 PPO trace 就此丢失)。

### ② 信息断层——契约细节从未送达 agent 必读的文件
核心规律:**"信息可获取"≠"信息已送达"**。agent 必读任务书(metaprompt/idea 记录),
不一定读任务书指向的外部文档。实证:
- TDC predictions.csv 表头规格在 `/workspace/docs/tdc_admet_tox_submission_spec.md`
  里躺着没被读 → agent 多带一列 smiles,strict fieldnames 相等判负
  (fullrun_tdc_01 第10次:1685 条预测全部完成,仅此一项判 0)。
- 3,600 秒实验上限只在预算文档 → agent 单次训练跑 5,400 秒超时
  (fullrun_tdc_01_20260828_130226_t)。
- 02 交付规格只写了 `predict(self, mlp)` 签名与返回形状,没写 mlp 是**对象** →
  agent `np.asarray(mlp)`,whest 实测 100/100 MLP 全崩
  (fullrun_arc_02_exitchk_20260828_154034,已对照 whestbench 0.16.0 源码核实接口)。

### ③ 严判门——fail-closed 不给部分分
表头列表全等(TDC 独有,全项目唯一)、trace 九字段逐一非空、适配器符号精确匹配、
常量预测正则封杀。防作弊初衷正当,但把①②的任何渗漏放大为 0 分。

## 三、两框架"同病不同灶"

|  | 01 AI-Researcher | 02 AI-Scientist-v2 |
|---|---|---|
| 断层主因 | 两容器边界 + 源码硬伤 | 两阶段管道(ideation→BFTS 只传 idea JSON) |
| 失败性质 | 确定性逐关开锁:每关死因不同,修好不复发,失败点单调后移 | 概率性漏交:同一门,每轮随机缺不同子集(3/5→2/5) |
| 有效对策 | 逐关修 + 搬运桥(原样搬运,绝不代写) | 规格注入 idea 记录 + 离场检查(框架自己的模型补自己的漏) |

01 源码硬伤清单(上游 bug,wrapper 暂存时打补丁):constant.py 无 PLATFORM、工具递归注册
失败、main() 少 references 参数、GPTClient 硬编码 gpt-4o-mini 且 chat() 四条路径静默返回
None、tiktoken 特殊 token 崩溃、agent 缓存文件名与实际产出不符(两个消费循环)、
copytree 跟随悬空符号链接、paper_agent 依赖未产出的目录。

## 四、模型对照实验(2026-08-28 夜,同一线束)

| topic | gpt-5.6-luna | DeepSeek-V4-flash |
|---|---|---|
| ARC(01) | **0.0875 分** | 五个交付物一个没写,42 门全灭 |
| PsyDef(01) | **0.1070 分** | 全部产物缺失 |

| BabyLM(01) | 走到论文撰写(第16关) | 4 分钟即死 |

**数据有效性修正(账单核实后)**:账户额度于 08-28 18:12 UTC 触零(此后所有请求 403)。
DS×ARC、DS×PsyDef 在额度耗尽前完成,为**有效对照数据**;DS×TDC 尾部 3 分钟与 DS×BabyLM
全程处于断粮状态,结果**作废**,恢复额度后需重跑。账单实测:最后 100 分钟双线并行仅烧
$4.25(DS $2.47 + luna $1.78,~$2/小时)——昨晚开跑时账户仅剩约 $4,额度耗尽的主因不是
当晚任务;按此燃烧率反推,四天战役总消耗约 $100-200 量级,远小于账户生命周期用量 $1345。

**解读:换模型不改变问题性质,只改变死亡位置。** 两个模型都死于交付合规而非研究能力;
模型越强走得越深,死在越细的规格上。分数 = 研究能力 × 交付合规率:线束 bug 摧毁第二项
(与模型无关,已修复);DeepSeek 连已送达的契约都不遵循,是第一项的模型能力差距——
两者被这组对照干净分离。

## 五、已落地并验证的修复(全部 01/02 作用域,commit 均附 run 证据)

1. **规格内联**:硬约束(文件 schema、表头、接口参数语义、时间上限)直接写进 agent 必读
   的任务书,而非只放在被引用文档 —— ARC 六连修验证,TDC/02 同法。
2. **搬运桥**:框架运行命令末尾,把 agent 工作区的产物**原样**搬到 /workspace 根,
   记录 provenance(handoff_relocation.json),绝不代写。
3. **离场检查**(02,独立适配器 exit_delivery_check.py):对照清单列缺失/不合规文件,
   由**框架自己的模型**基于**框架自己的产出**补写/改键名,全程审计,可一行禁用。
   [裁决点:需团队批准后其结果方可发表]
4. **源头兜底**:None/别名/断链类 bug 在定义处修,不在消费点打地鼠
   (write_temp_log→structure.split→f.write 三连崩的教训)。
