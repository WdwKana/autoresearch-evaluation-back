# 契约控制力的定量验证（离线,基于留存 run）

2026-08-31 · 命题: "开头注入的契约能否控制 agent 的产出?" · 方法: 对全部留存 run 做剂量-反应分析。

## 公式

契约控制力 = 送达率 × 保持率 × 激励相容度

## 实验一 01×ARC (14 run): 送达 ⇒ 必合规

唯一自变量 = 简报是否物理进入 agent 世界(深处 dataset_candidate);信息在 inputs 里全程可获取(8/8 字段)。
- 未送达 4 run → trace 无/0/9/1/9/无 (必不合规)
- 已送达 9 run → trace 9/9 连续 8 次 (唯一例外 DS run 死于容器通道,与规格无关)
**零例外的确定性翻转 → 对"工具循环+整段嵌入+任务即契约"的执行模型,前置契约可 100% 控制。**

## 实验二 02×ARC (17 run, 全节点扫描): 送达也只能概率控制

- 路由铁律: Stage1 104节点 / Stage2 62节点 / Stage4 28节点 中含交付文件名的代码 = **0**;
  全部命中集中在 Stage3(每个到达 S3 的 run 1-7 个节点)——agent_manager 字段裁剪的全量数据实锤。
- 剂量-反应: idea 无注入 → 根交付 8 连 0/5;注入后 → 2/5, 3/5, 原生 5/5(仅一次)。
- 提及≠交付: 无注入 run 的 S3 节点也提文件名(ideation 自发转写的残缺版),根交付仍 0/5。

## 实验三 标本: agent 的"自己的想法"现行

无注入 02 run 深处有框架自写的 experiment_trace.json,字段为
timestamp/seed/device/datasets/summary/score/score_source/score_artifact/submission_artifact
—— 同名文件、异质本体;其中 score_source 等三个名字恰是契约 result_fields 的碎片:
**ideation 模型把见过的契约嚼碎掺进了自己的 trace 观念——有损自然转写的直接标本。**

## 结论

| | 01 | 02 |
|---|---|---|
| 送达率 | 0(拓扑墙)→修复后 1 | 0→idea 通道,但路由裁至 1/4 阶段 |
| 保持率 | ≈1(转录常驻) | S3 内重发,但逐节点全量重写=逐次重掷骰子 |
| 激励相容 | 1(任务书即目标) | 0(适应度只看指标) |
| 实测控制力 | 100% (8连9/9) | ~1/3 (原生 5/5 仅 1 次) |

**metaprompt 约束不住的不是 agent,而是"带自身目标函数的执行系统"。**
激励相容度=0 时,措辞只能提高概率不能保证——措辞改不了代码里的适应度函数。
出路必在文本之外: 改目标函数(侵入)或优化结束后加确定性交付步骤(离场检查)。
